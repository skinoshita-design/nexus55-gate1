# Gate1 提出物

社内問い合わせ管理システム「ステータス変更・担当者割り当て機能」
技術構成:Node.js + Express + SQLite(better-sqlite3)+ EJS
(仕様書に技術の指定が無かったため、2.3 のテーブル定義・N-01 のトランザクション・N-02 の排他制御をそのまま実装できる、データベースを使った構成を選んだ)

## 1. 起動手順

前提:Node.js 18 以上(動作確認は v22)

```bash
npm install      # 依存パッケージのインストール
npm run seed     # DBを初期状態に戻す(初回は npm start 時に自動作成されるので省略可)
npm start        # http://localhost:3000 で起動
```

| コマンド | 内容 |
|---|---|
| `npm start` | アプリ起動 |
| `npm run seed` | DB(data.sqlite)を削除し、シードデータで作り直す |
| `npm run db` | inquiries と inquiry_histories の中身を表示(closed_at 等の確認用) |

※ `.npmrc` で `ignore-scripts=true` を指定している。better-sqlite3 は Windows / Mac / Linux 用のビルド済みバイナリを同梱しているため、C++ のビルド環境が無くても `npm install` が通る。

| V-03 担当者プルダウンの五十音順 | **一部未達** | 氏名を `localeCompare('ja')` で並べているが、漢字の読みが分からないため文字コード順になる。シードでは「佐藤 花子 → 田中 一郎 → 鈴木 次郎」と表示され、正しい五十音順(佐藤 → 鈴木 → 田中)になっていない。正しく並べるにはふりがなのカラムが必要だが、仕様外の追加になるため追加していない |

### 6-3. もしこの要件定義書が無く、「問い合わせのステータスを変えられるようにして」とだけ言われていたら、何を確認しに行きましたか。

- ステータスは何種類あるか。それぞれの名前と意味は何か
- どのステータスからどのステータスへ変更してよいか(戻す操作や飛ばす操作は可能か)
- 完了した問い合わせを再び開ける(再オープンできる)か
- ステータス変更は誰が行えるか(管理者と一般担当者で違いはあるか)
- 担当者の割り当ても今回の範囲に入るか。入るなら誰が誰に割り当てられるか
- 担当者を「未割り当て」に戻せるか。戻せるなら条件は何か
- 退職者など無効なユーザーを担当者に選べるか
- ステータス変更に連動して自動で変わる項目はあるか(担当者の自動設定、完了日時など)
- 変更履歴を残す必要があるか。残すなら何を、何件まで表示するか
- 変更時にコメントを入力させるか。保存先や文字数の上限はどうするか
- 成功時・失敗時のメッセージ文言は決まっているか
- 変更ボタンはどの画面のどこに置くか。選べない選択肢は非表示か、非活性か
- 同時に2人が同じ問い合わせを更新したときはどうするか(排他制御)
- 更新途中で失敗した場合、どこまで元に戻すか(トランザクション)
- 権限チェックは画面だけでよいか、サーバー側でも必要か
- 依頼者(社員)への通知は必要か(メールなど)
- 優先度など他の項目も変更できるようにするか
- 既存の一覧画面・検索条件にステータスを反映する必要があるか
- 期限(いつまでに)と、完成の判断基準は何か
